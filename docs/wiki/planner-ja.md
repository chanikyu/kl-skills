# planner

その分野のやり方でプロジェクトを計画し、長期・中期・短期の目標をつなげたまま保ち、計画から外れた作業を指摘する。

## Claude での使い方

「planner でこれを計画して」や「X のロードマップを書いて」と言う。計画の依頼には、`skill-match` がこのスキルの名前を挙げる。

## 何をするか

1. まず枠組みを決める: どの分野か（事業戦略、サービスとウェブ、UI/UX、プロダクト、コンテンツ、ソフトウェア、広告、生産と品質）、どの期間か、どのレベルか。
2. 次に順番に進める: 問題を調べ、目標を立て、実現可能性を確かめ、機能を定め、要件と仕様を書き、フローとワイヤーフレームを設計し、関係チーム（サブエージェントが演じる）と日程を決める。
3. 目標には `L1` → `M1.2` → `S1.2.3` と番号を振る。こうすると、親のないタスクが機械的に見つかる。
4. 作業は `- [YYYY-MM-DD] S1.1.1 …` の形で記録する。計画外の作業には `(계획 밖)`（「計画外」）と理由を付け、終わった目標には `완료`（完了）か `done` を付ける。ずれのチェックは `(계획 밖)` をそのとおりの文字列で探す。

## ファイルとスクリプト

| スクリプト | すること |
| --- | --- |
| `check_plan.py <plan.md>` | 欠けているセクション、親や目標値のない目標、目標に結びつかない機能を指摘する |
| `check_drift.py <plan.md>` | 黙って行われた計画外の作業、期限を過ぎた目標、誰も手を付けていない長期目標を指摘する |

計画のテンプレートは `assets/plan-template.md`、分野ガイドは `references/domains.md` である。

## このスキルを支えるフック

`plan-drift` は計画が書かれたときにそれをチェックし、`after-bash` はコミットのたびにずれをチェックする。どちらも報告するだけで、止めることはない。

## 制限

ずれは進捗ログとコミットメッセージから判断する。痕跡を残さない作業は見えない。
