# 작동 방식

## 스킬, 훅 게이트, 위키

<img src="../../assets/parts.png" alt="메시지가 Claude Code 로 간다. Claude Code 는 스킬을 읽고, 훅 게이트의 검사를 받고, 알게 된 것을 위키에 남긴다." width="100%" />

- **스킬**(= Claude 에게 일하는 방법을 알려 주는 설명서)은 일을 어떻게 하는지 말한다. Claude Code 는 대화가 스킬의
  설명과 맞을 때 그 스킬을 읽는다. 맞는지는 모델(= Claude 자신)이 스스로 판단한다. 그래서 늘 읽힌다는 보장은 없다.
- **훅 게이트**(= 정해진 순간마다 저절로 도는 검사)는 누가 기억하든 말든 그 순간에 돈다. `skill-match` 가 위의 빈틈을
  메운다. 이 게이트는 메시지마다 각 스킬의 트리거 단어(= 그 스킬을 부르는 낱말)와 맞춰 보고, 맞는 스킬의 이름을 알려 준다.
  트리거 단어는 영어와 한국어로만 있다. 다른 언어로 말하면 Claude 가 스킬 설명을 직접 맞춰 본다.
- **위키**(= 주제마다 한 페이지씩 쓰는 지식 노트 모음)는 알게 된 것을 남긴다. `wiki-recall` 이 그것을 다시 꺼내 온다.

| --- | --- | --- | --- |

| 메시지 들어옴 | `wiki-recall` | 관련 위키 페이지를 붙인다 | — |
| 메시지 들어옴 | `skill-match` | 이 메시지에 맞는 스킬의 이름을 알려 준다 | — |
| 메시지 들어옴 | `checklist-start` | 이 지시의 체크리스트를 어디에 쓸지 알려 준다 | — |
| 파일 쓰기 | `wiki-index-check` | 목차에 빠진 위키 페이지를 알린다 | — |
| 파일 쓰기 | `wiki-graph` | 위키 그래프를 다시 그린다 | — |
| 파일 쓰기 | `prose-check` | 위키 페이지에서 읽기 어려운 자리를 알린다 | — |
| 파일 쓰기 | `code-check` | 모호한 Python 이름과 빠진 docstring(= 함수 맨 위에 쓰는 설명 글)을 알린다 | — |
| 파일 쓰기 | `plan-drift` | 계획서의 틀과 이탈(= 계획에서 벗어난 일)을 확인한다 | — |
| Bash 실행 | `after-bash` | 셸(= 명령을 직접 치는 창)에서 한 위키 수정과 커밋을 알아챈다 | — |
| 답 끝 | `wiki-sync` | 페이지를 어떻게 고쳤든 그래프를 최신으로 맞춘다 | — |
| 답 끝 | `answer-check` | 답을 검사한다: 되묻기, 작업 보고, 길이, 글, 분야 용어 | 한 번 |
| 답 끝 | `checklist-check` | 체크리스트 항목이 다 끝났는지 확인한다 | 한 번 |

## 답이 되돌아갈 때

두 게이트는 답이 사용자에게 닿기 전에 Claude 에게 되돌려 보낼 수 있다. `answer-check` 와 `checklist-check` 다.
그러면 Claude Code 는 `Stop hook feedback:` 과 그 이유를 보여 준다. Claude 는 답을 고치거나 남은 항목을 끝낸다.
게이트마다 이 일은 **한 턴**(= 메시지 하나를 받고 답 하나를 내는 한 차례)**에 한 번**만 한다.
두 번째에는 남은 것을 알리기만 한다. 그래서 한 턴이 끝없이 되풀이되는 일은 없다.

## 게이트가 판단하지 못할 때

게이트는 그 턴을 그냥 통과시킨다. 오류로 멈추는 게이트는, 그 게이트가 도는 순간이 오는 모든 세션을 망가뜨린다.
그래서 모든 게이트는 이해하지 못하는 입력을 받으면 아무 탈 없이 끝난다.
