# natural-answering

説明のつながりを省かないことで、読み手が一度で追える回答、報告、文書を書く。

## Claude での使い方

何も言わなくてよい。`answer-check` ゲートがすべての回答を読む。

## 何をするか

1. 次の8つは決して省かない: 用語が初めて出た場所でのその意味、数値から結論への一歩、数値が何と比べられているか、その作業をした理由、文の主語、日常の言葉での単位、件数の内訳となる項目、レビュアーやツールの指摘を言い直した平易な言葉。
2. 最初の一文で、聞かれた問いに答える。
3. 回答は1画面に収める。それより長くなるものは、短い要約を付けた文書にする。
4. コードを変更したあとの報告は6つの段階に従う: 結果、要約、変更点、検証、問題と制限、次の対応。
5. 用語はその分野の言葉のまま使う。ガイドライン・論文・あなた自身のスライドにある言葉を使い、平易な意味は括弧で添える。似た言葉を作らない。

## ファイルとスクリプト

| スクリプト | すること |
| --- | --- |
| `check_prose.py <files>` | 定義されていない用語や略語、長い文、その他の省略を指摘する |
| `check_terms.py <files>` | 分野で使わない言葉を見つける（対応表は `data/domain-terms.tsv`）。.pptx と .docx の中の文章も読む |

ルールは `data/` 内のデータであり、作業報告と文書の骨組みは `references/` にある。

## このスキルを支えるフック

`answer-check` は回答に抜けがあると1回だけ差し戻す。対象は、同じ質問がもう一度された場合、ファイルを変更したのに6段階の報告がないターン、1画面を超える回答、文章チェックの指摘である。`prose-check` は wiki ページを読む。

回答、そのターンに書いたファイル、回答が指したスライドに `data/domain-terms.tsv` の誤った言葉があるときも1回だけ差し戻し、分野の言葉を示す。用語を直したら、そのファイルに1行足す。

## 制限

チェックは韓国語を優先している。韓国語以外の文章については、定義されていない略語と長い文だけをチェックする。
