# pipeline-debug

코드가 실패하거나 틀린 결과를 낼 때 쓴다. 문제가 드러난 줄을 고치지 않는다.
대신 파이프라인(= 데이터가 차례로 거치는 단계들의 줄)을 거슬러 올라가 원인을 찾는다.

## Claude 에서 쓰기

"이 에러 디버깅해줘" 라고 말한다. 에러, 트레이스백(= 에러가 난 지점까지의 호출 기록), 실패한 실행이면 `skill-match` 가 이 스킬 이름을 알려 준다.

## 하는 일

1. 데이터가 거친 단계들을 지도처럼 그린다.
2. 단계마다 들어간 것과 나온 것을 기대한 것과 견준다. 개수, 열, 실제 값 몇 개를 본다.
3. 출력이 처음 틀린 단계가 원인이다. 에러는 보통 그보다 뒤의 단계에서 나타난다.
4. 그 단계에서 문제를 다시 일으켜 본다. 실패하는 검사로 문제를 고정하고, 그 자리에서 고친다. 그다음 뒤의 모든 단계를 다시 돌린다.

## 파일과 스크립트

| 스크립트 | 하는 일 |
| --- | --- |
| `probe.py [--rows N] FILE ...` | 단계 사이에 넘기는 파일의 행, 열, 빈칸, 첫 몇 줄을 보여 준다 |

## 한계

중간 파일이 있어야 한다. 단계 사이에 아무것도 남기지 않는 파이프라인은, 중간 파일을 저장하게 바꿔서 다시 돌려야 한다.
