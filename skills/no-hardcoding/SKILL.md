모든 프로젝트 · 모든 세션 공통. **코드·스크립트·노트북 셀에 값을 적어 넣으려는 모든 순간**에 적용한다.
(매핑표, 물질·종·파일 목록, 경로, 임계값, 파라미터, 조건 집합 전부 포함)

CLAUDE.md §19의 정본.

## 문제

하드코딩은 당장 돌아가기 때문에 문제로 보이지 않는다. 깨지는 지점은 나중이고, 네 가지다.

1. **정본이 둘이 된다.** 파일에 있는 목록을 코드에 다시 쓰면 같은 사실이 두 곳에 산다.
   한쪽만 고쳐지는 순간 조용히 틀린 결과가 나온다. `source-of-truth.md`가 막으려는 drift를
   내 손으로 만드는 셈이다. 에러도 안 난다.
2. **조건을 기록할 수 없다.** 임계값이 코드 안에 있으면 재실행 조건을 파일명이나 인자로 남길 수
   없다(Skill `analysis-artifacts` S2). 어떤 값으로 돌린 결과인지 나중에 댈 수 없다.
3. **남이 못 돌린다.** 절대경로가 박힌 스크립트는 그 머신에서만 돈다.
4. **검토가 흐려진다.** 매핑표가 코드 안에 있으면 표를 고친 것이 코드 변경으로 보인다.
   데이터 수정과 로직 수정이 같은 diff에 섞여 리뷰가 둘 다 놓친다.

## 규칙 (반드시 항상)

### H1. 파일에 이미 있는 값을 코드에 다시 쓰지 않는다

가장 중요한 규칙이다. 코드에 목록·집합·매핑을 쓰려 할 때 **먼저 그 값이 이미 파일에 있는지
찾는다.** 있으면 **읽는다.** 베껴 쓰지 않는다.

```python
# 나쁨 — ko_list.tsv 에 이미 있는 목록을 코드에 베껼
have_evidence = {"asp_L", "cys_L", "fum", "glu_L", "his_L", "ile_L", ...}

# 좋음 — 정본 파일에서 읽는다
kos = pd.read_csv(KO_LIST, sep="\t")
have_evidence = set(kos.metabolites.str.split(";").explode())
```

베껴 쓰면 정본 파일이 바뀌어도 코드는 모른다. 그게 §14가 말하는 drift다.

### H2. 데이터는 데이터 파일로 뺀다

매핑표·별칭 사전·분류 목록·조건 집합은 **데이터**다. 코드가 아니다.
TSV·CSV·JSON·YAML로 빼고 코드는 그것을 읽는다. 스크립트 옆에 두고 함께 커밋한다.

판단 기준: **"이 값이 바뀔 때 로직도 바뀌는가?"** 아니라면 데이터다.
항목이 5개를 넘어가는 사전·목록은 거의 항상 데이터다.

데이터 파일로 빼면 덤으로 생기는 것 — diff가 읽히고, 사람이 직접 고칠 수 있고,
출처 열(어디서 온 값인지)을 붙일 수 있다.

### H3. 경로는 계산하거나 인자로 받는다

절대경로를 박지 않는다. 순서는 이렇다.

1. 스크립트 위치에서 상대로 계산 — `os.path.dirname(os.path.abspath(__file__))`
2. CLI 인자 — `--repo`, `--in`, `--out`
3. 환경변수 — 여러 스크립트가 같은 뿌리를 공유할 때

리포지토리 뿌리를 `"/Users/<이름>/workspace/..."` 로 박는 것은 H3 위반이다.

### H4. 임계값·파라미터는 바꿀 수 있게 둔다

컷오프·p 문턱·반복 수·시드·배치 크기는 **CLI 인자로** 노출한다. 기본값은 코드에 둬도 되지만
바꾸려고 코드를 고쳐야 하면 안 된다. 돌린 값은 로그와 결과 파일명에 남긴다(Skill `analysis-artifacts`).

### H5. 코드에 둬도 되는 것

- 바뀌지 않는 상수: 물리상수, 단위 변환, 수학 상수
- 외부 규격이 정한 값: 프로토콜 포트, 포맷 매직넘버, API 버전 문자열
- 로직과 한 몸인 분기 조건: 그 값을 바꾸면 알고리즘이 달라지는 경우

이름 없는 숫자는 금지다(`coding-style.md` Magic Numbers). 상수로 쓸 때도 이름을 붙이고
**왜 그 값인지** 주석 한 줄을 남긴다.

### H6. 어쩔 수 없이 코드에 둔다면 — 출처를 적고 검증을 붙인다

외부 파일로 뺄 수 없는 사정이 있으면(한 번 쓰는 셀, 외부 파일이 없는 값):

1. **어디서 온 값인지** 주석에 쓴다 (논문·DB·문서·사람)
2. **그 값이 아직 맞는지 확인하는 한 줄**을 붙인다 — 목록이면 정본과 길이·원소 비교,
   임계값이면 범위 assert
3. 두 번째로 같은 값을 쓰게 되면 **그때는 파일로 뺀다**

## 어디에 둬야 하나

| 무엇 | 두는 곳 |
|---|---|
| 매핑표·별칭 사전·분류 목록 | 스크립트 옆 `*.tsv` / `*.json` (커밋) |
| 대상 목록 (종·물질·파일·샘플) | 정본 파일에서 읽기. 없으면 `targets.tsv` |
| 경로 | `__file__` 상대 계산 · CLI 인자 · 환경변수 |
| 임계값·파라미터·시드 | CLI 인자 (기본값은 코드) |
| 자격증명·토큰 | 환경변수·시크릿 매니저 (`security.md`) |
| 물리상수·단위 변환 | 코드 (이름 붙인 상수) |

## 체크리스트 — 코드에 값을 쓰기 직전

- [ ] 이 값이 **이미 어떤 파일에 있나?** 찾아봤나? (H1)
- [ ] 항목이 5개를 넘는 사전·목록인가? → 데이터 파일로 (H2)
- [ ] 절대경로를 쓰고 있지 않나? (H3)
- [ ] 이 임계값을 바꾸려면 코드를 고쳐야 하나? → 인자로 (H4)
- [ ] 이름 없는 숫자를 쓰고 있지 않나?
- [ ] 코드에 둘 수밖에 없다면, 출처 주석과 검증 한 줄을 붙였나? (H6)

## 금지

**파일에 있는 목록·매핑을 코드에 베껴 쓰기(정본 둘 → drift)** · 매핑표·사전을 코드 안에 두기 ·
절대경로 박기 · 임계값을 코드에만 두고 인자로 안 빼기 · 이름 없는 숫자 ·
출처 없는 상수 · "일단 박고 나중에 빼기"
